# Планировщик жизни / Life Planner

Личный планировщик: финансы, задачи, покупки, календарь, здоровье, цикл, карты и криптоадреса —
в одном приложении. Одна кодовая база даёт **веб (PWA)** и **Android-приложение** (Capacitor).

**Живая версия:** https://asefusisasis.github.io/planner/

## Возможности
- 🏠 **Главная** — живые часы, тикер курсов, блок «Требует внимания» (просрочки, превышение
  бюджета, ближайший платёж, события), настраиваемые виджеты + быстрый ввод трат с категориями.
- 💰 **Финансы** — доходы/расходы и баланс, категории с бюджетами, кольцевая диаграмма, поиск и
  фильтры, повторяющиеся платежи (в т.ч. кредиты с датой окончания), налог % от доходов,
  отчёт для налоговой с выгрузкой CSV, тренд за 6 месяцев.
- 💱 **Валюты** — 25 фиатных + 11 криптовалют. Курс фиксируется **на момент операции**, поэтому
  прошлые записи не «плывут» при изменении курса.
- ✅ **Дом (задачи)** — приоритеты, повторяемость, сроки, описание и подзадачи-шаги, перенос
  просроченного, группировка (просрочено / сегодня / ближайшие).
- 🛒 **Покупки** — списки, количество и цены, прогресс, итоги, «→ в траты», дата покупки.
- 📅 **Календарь** — месячный вид с событиями по времени + режим «Активность» (heatmap).
- ❤️ **Здоровье** — нормы калорий/БЖУ/воды/ИМТ (Миффлин-Сан Жеор), дневник веса и замеры, меню,
  дневник еды, трекер воды, тренировки. Импорт веса из **Health Connect** (Android, только чтение).
- 🌸 **Цикл** — прогноз диапазоном с уровнем уверенности, календарь, дневник симптомов, личные
  закономерности и предменструальное окно **по собственным отметкам**. Данные цикла
  **не покидают устройство** (см. «Приватность»).
- 👛 **Кошелёк** — банковские карты (бренд, маскирование, копирование), скидочные (штрихкод
  Code128) и криптоадреса с обязательным указанием сети и проверкой формата.
- 🔒 **Защита данных** — единый TOTP-ключ (аутентификатор), биометрия/PIN, секрет в Android
  Keystore. Номера карт шифруются AES-GCM.
- 📱 **Android** — APK через Capacitor, локальные уведомления, виджеты рабочего стола
  (Сегодня / Вода / Цикл / Покупки).

## Стек
React 19 · TypeScript (strict) · Vite · Tailwind v4 · zustand · react-i18next · vite-plugin-pwa ·
Vitest · Capacitor 8 (Android) · Supabase (аккаунты и облачный синк).

## Запуск и разработка
```bash
npm install
npm run dev       # дев-сервер (обычно http://localhost:5173)
npm run build     # tsc + прод-сборка в dist/
npm run preview   # предпросмотр прод-сборки
npm test          # тесты (Vitest)
```

Сборка Android:
```bash
npm run build && npx cap sync android
cd android && ./gradlew assembleDebug
```

### Структура
```
src/
  modules/        # экраны: dashboard, expenses, home, shopping, calendar, health, cycle, cards, settings
  components/     # общие: ui, Heatmap, Donut, Barcode, LineChart, QrCode, SearchModal, Layout
  services/       # rates (курсы), cloudSync (Supabase), github (резервный синк),
                  # merge (3-way), notifications, androidWidget
  store/          # zustand: данные + синхронизация + защита
  lib/            # чистая логика с тестами: cycle, taxReport, healthImport, vault, cryptoAddress…
  types.ts        # модель данных (AppData)
android/          # нативный проект: виджеты, Keystore, Health Connect
```

Правило раздела `lib/`: там лежит **чистая, покрытая тестами** логика без React и без Capacitor.
Расчёты цикла, налоговый отчёт, разбор криптоадресов, правила импорта веса — всё проверяется
юнит-тестами, а UI только отображает результат.

## Синхронизация

Есть два независимых способа. Обычному пользователю нужен только первый.

### 1. Аккаунт (Supabase) — основной
Регистрация по почте прямо в приложении: **Настройки → Аккаунт**. Данные синхронизируются между
устройствами автоматически, ничего настраивать не нужно.

Как устроено: все коллекции лежат в одной таблице `records` (ключ — пользователь + коллекция + id),
доступ ограничен политиками RLS — каждый видит только свои записи. Синхронизация инкрементальная
(курсор по `server_updated_at`), конфликты решаются 3-way merge по `updatedAt`.

Схема БД и функция удаления аккаунта — в [`supabase/schema.sql`](supabase/schema.sql). Чтобы
поднять свой экземпляр: создать проект в Supabase, выполнить этот файл в SQL Editor и прописать
URL и **anon**-ключ в `.env` (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`). Ключ `service_role`
в приложении не используется и в репозитории его быть не должно.

### 2. Приватный GitHub-репозиторий — альтернатива
Для тех, кто хочет держать данные строго у себя: всё лежит одним файлом `data.json` в **приватном**
репозитории, приложение читает и пишет его через Contents API. Настраивается в
**Настройках → Синхронизация**: нужен репозиторий и токен с правом `Contents: Read and write`.
Токен хранится только локально и в `data.json` не попадает.

## Приватность

- **Данные цикла не уходят в общее облако.** Они хранятся локально; при синке через личный
  GitHub-репозиторий шифруются ключом «Защиты данных» (AES-GCM) и лежат там шифротекстом.
- **Номера карт** шифруются тем же ключом. Секрет ключа — в Android Keystore, вне WebView.
- **Криптоадреса не шифруются** намеренно: адрес получения публичен по своей природе, его и так
  сообщают отправителю, а под замком он потерял бы смысл.
- **Health Connect — только чтение веса.** Приложение ничего не записывает в общее хранилище ОС
  и не передаёт туда данные цикла.
- Публичные страницы для Google Play: [`public/privacy.html`](public/privacy.html) и
  [`public/delete-account.html`](public/delete-account.html).

## Деплой (GitHub Pages)
Пуш в `main` запускает workflow, который собирает проект и публикует `dist/`.

## Установка как приложение (PWA)
В Chrome на ПК — иконка установки в адресной строке; на Android — «Добавить на главный экран».
Приложение работает офлайн, данные синхронизируются при появлении сети.
