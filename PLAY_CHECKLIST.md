# Публикация в Google Play — чеклист

Кода здесь почти нет: всё, кроме подписи, делается в Play Console. Данные
для форм ниже **выведены из кода**, а не по памяти — источник указан для
каждого пункта, чтобы при изменениях можно было перепроверить.

---

## 1. Ключ подписи (делается один раз)

Ключ создаёте **вы**: пароль к нему никто, кроме вас, знать не должен.

```bash
keytool -genkeypair -v -keystore planner-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias planner
```

Положите `planner-release.jks` в `android/`, скопируйте
`android/keystore.properties.example` → `android/keystore.properties` и
впишите пароли. Оба файла в `.gitignore`, в репозиторий не попадут.

> **Потеря `.jks` или паролей = невозможность обновлять приложение** под
> тем же листингом. Сделайте резервную копию отдельно от компьютера.

Сборка релиза после этого:

```bash
npm run build:app && cd android && ./gradlew bundleRelease
```

Готовый файл: `android/app/build/outputs/bundle/release/app-release.aab`.
Если `keystore.properties` нет, сборка не упадёт — просто выйдет
неподписанный бандл, который Play не примет.

**Проверьте `versionCode` перед каждой загрузкой** — сейчас в
`android/app/build.gradle` стоит `1`. Play не принимает повторно тот же
номер; увеличивайте на единицу при каждой заливке.

## 2. Data Safety — что отвечать

Раздел заполняется по факту. Ошибка здесь — не «неточность в анкете», а
нарушение политики с приостановкой листинга.

### Собираются и передаются на сервер (Supabase)

Данные уходят в облако **только после входа в аккаунт**. Без аккаунта
приложение полностью локальное — это стоит отметить в поле пояснения.

| Категория Play | Что именно | Откуда это видно в коде |
|---|---|---|
| Personal info → **Email address** | почта аккаунта | `services/supabase.ts`, вход/регистрация |
| Personal info → **Name** | имя для приветствия, необязательное | `Settings.userName` |
| Photos → **Photos** | аватар, необязательный | `services/avatar.ts`, приватный bucket |
| Financial info → **Purchase history** | траты, доходы, повторяющиеся платежи | `COLLECTIONS` в `services/cloudSync.ts` |
| Health and fitness → **Health info** | вес, замеры, питание, вода, тренировки | `weightLog`, `measurements`, `foodLog`, `waterLog`, `workoutLog` |
| App activity → **Other user-generated content** | задачи, списки покупок, события календаря, заметки | `homeTasks`, `shoppingLists`, `calendarTasks` |

Для **всех** строк:
* Collected — **да**; Shared — **нет** (третьим лицам не передаётся);
* Processed ephemerally — нет (хранится);
* Required or optional — **optional** (работает и без аккаунта);
* Encrypted in transit — **да** (HTTPS);
* Can request deletion — **да** (страница удаления аккаунта уже есть).

### НЕ собирается — отвечать «нет»

* **Location.** Разрешения геолокации в манифесте нет; погода — по городу,
  который пользователь вводит руками. Проверено: в манифесте только
  `INTERNET`, `USE_BIOMETRIC`, `health.READ_WEIGHT` (+ `POST_NOTIFICATIONS`
  добавляет плагин уведомлений).
* **Контакты, СМС, журнал звонков, файлы, микрофон, камера.**
* **Аналитика, реклама, крашлитика, идентификаторы устройства.** В
  зависимостях нет ни одного трекера — проверено по `package.json`
  (33 пакета, совпадений с analytics/firebase/admob/sentry и т.п. нет).
* **Данные цикла.** Хранятся только на устройстве и намеренно исключены из
  синхронизации — см. комментарий в `COLLECTIONS`. В облако не уходят.

### Номера карт — решено 02.08

**Payment info в форме заявлять НЕ нужно.** Незашифрованные банковские
карты в облако не выгружаются вовсе: фильтр в `cloudPush` пропускает из
коллекции `cards` только записи с `enc: true` (номер зашифрован мастер-
ключом) и скидочные (там код скидки, не платёжные данные). Уже уехавшие
до этого решения строки удаляются с сервера при синхронизации
(`purgePlainCardsFromCloud`).

Если пользователь включит «Защиту данных», номера начнут синхронизироваться
— но уже как шифротекст, который без мастер-ключа бесполезен. Ключ на
сервер не попадает никогда.

В строке **Financial info → Purchase history** (траты и доходы) это ничего
не меняет — она остаётся.

## 3. Content rating

Анкета короткая, по этому приложению все ответы отрицательные:

* насилие, кровь, пугающий контент — нет;
* сексуальный контент, нагота — нет;
* ненормативная лексика — нет;
* алкоголь, табак, наркотики — нет;
* азартные игры и симуляция азартных игр — нет;
* пользовательский контент и обмен им — **нет** (общий список покупок
  доступен только по приглашению между двумя аккаунтами, публикации и
  ленты нет);
* обмен местоположением — нет;
* покупки внутри приложения — нет.

Ожидаемый результат: **3+ / Everyone**.

Отдельно спросят про **финансовые функции**: приложение не проводит
платежей, не даёт займов и не является финансовым сервисом — это личный
учёт. Отвечать соответственно.

## 5. Health Connect — отдельная декларация

Google требует её от всех приложений с доступом к медданным. Заявляемое:

* запрашивается **одно** разрешение: `health.READ_WEIGHT` — только чтение
  веса, только для подстановки в дневник веса;
* запись в Health Connect **не производится**;
* медданные третьим лицам не передаются и в рекламе не используются;
* экран обоснования уже реализован — `VIEW_PERMISSION_USAGE` +
  `ACTION_SHOW_PERMISSIONS_RATIONALE` в манифесте, Google это проверяет.

Скорее всего попросят короткое видео сценария: открыть Здоровье → раздел
веса → подключить Health Connect → выдать разрешение → показать
подтянувшийся вес.

## 6. Листинг — черновик

**Название (до 30):** Планировщик — жизнь и финансы

**Краткое описание (до 80):**
Траты, задачи, покупки, календарь и здоровье — в одном приложении, офлайн.

**Полное описание:**

> «Планировщик» собирает в одном месте то, что обычно разбросано по пяти
> разным приложениям: деньги, дела по дому, списки покупок, календарь и
> здоровье.
>
> **Финансы.** Траты и доходы по категориям, бюджеты, повторяющиеся
> платежи и кредиты с датой окончания, налог с доходов, отчёт для
> налоговой с выгрузкой CSV. Несколько валют с курсами Нацбанка, включая
> криптовалюты. Операцию можно добавить из текста банковского уведомления.
>
> **Дом и покупки.** Задачи с приоритетами, шагами и повторением. Списки
> покупок, в том числе общий список на двоих — удобно, когда в магазин
> идёт кто-то один.
>
> **Здоровье.** Вес, замеры, вода, питание и тренировки. Норма калорий и
> БЖУ считается по вашему профилю. Вес можно подтянуть из Health Connect.
>
> **Приватно по умолчанию.** Без регистрации всё работает локально на
> устройстве. Аккаунт нужен только чтобы синхронизировать данные между
> телефоном и компьютером. Рекламы и трекеров нет.
>
> **Защита данных.** Номера карт и данные цикла можно закрыть отдельным
> ключом с разблокировкой по отпечатку.

**Скриншоты:** нужно минимум 2, лучше 4–6. Показать Главную, Финансы,
Здоровье, Кошелёк. Снимать в светлой теме — на витрине она читается лучше.

**Иконка** и **feature graphic 1024×500** — feature graphic ещё нет,
без него листинг не опубликовать.
